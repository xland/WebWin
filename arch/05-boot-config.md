# 应用启动与配置

## 启动方式一：读取同目录 `package.json`

提供给开发者的 `exe` 启动时：

1. 自动读取 **exe 同目录下**的 `package.json` 文件
2. 解析其中**与 WebWin 框架有关的配置**
3. 按配置启动应用

配置项举例（用户已提及）：

- 加载哪个 HTML 文件（入口页面）
- 使用什么字符串作为**应用 ID**

> 复用 `package.json` 的考虑：前端工程通常已有该文件，
> 开发者无需再维护一份框架专用配置文件。
> 框架只读取其中与 WebWin 相关的字段，其余字段忽略。

## 已定决策

| 议题 | 决策 |
| --- | --- |
| 配置字段组织方式 | **集中在 `"webwin": { ... }` 子对象下**（避免与前端工具链字段冲突） |
| `package.json` 位置约定 | **`exe` 与 `package.json` 必须在同一目录下**，否则 exe 不认该文件 |
| 配置异常时的行为 | **显示 exe 内置的默认页面**（见下） |

### 内置默认页面

框架在 `exe` 内内置一个默认页面。当配置不可用时显示它，
覆盖以下情况：

- `package.json` 缺失
- `package.json` 不在 exe 同目录（exe 不认）
- `webwin` 配置缺失或字段缺失
- 指定的入口 HTML 文件不存在（含路径解析失败）

> 体积提醒：该默认页面会进入 `exe`、成为**最终分发物**的一部分
> （见 `00-overview.md` 体积口径），应保持精简，避免内联大体积资源。

> `webwin` 子对象的**字段详解**见 `06-package-json.md`。

## 启动方式二：命令行指定应用目录

exe 启动时若命令行包含 `--path=<dir>`，则**不**再读 exe 同目录的 `package.json`，
而是到 `<dir>/package.json` 加载。

```bat
WebWin.exe --path=D:\apps\myapp
WebWin.exe --path="D:\apps\my app"   REM 路径含空格时按标准命令行引号规则写
```

行为：

- 路径可以**绝对**或**相对**（相对当前工作目录）
- 首个 `--path` 生效，后续忽略
- 指定的目录下没有 `package.json` 时，按「配置不可用」处理（见上文默认页面）
- 与方式一互斥：出现 `--path` 时整次启动以命令行覆盖为准

### 路径基准统一

不论走哪种启动方式，**所有相对路径都以 `package.json` 所在目录为基准**：

- 入口 HTML（`webview.path`）的相对路径
- 其余按"应用目录"解析的相对路径（将来扩展）

这样开发者写 `"webview": { "path": "./web" }` 时，无论 `package.json` 在 exe 同目录还是 `--path` 指明的目录，含义都一致。

### 已定

| 议题 | 决策 |
| --- | --- |
| 命令行格式 | **`--path=<dir>`**（用 `=` 直接连值，避免被切成两个参数） |
| 参数解析方式 | 用 `CommandLineToArgvW` 按标准命令行规则切分（自动处理空格/引号） |
| 与方式一的关系 | 互斥：出现 `--path` 整次启动以命令行覆盖为准 |
