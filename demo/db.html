连接（Db.open / close）

Db.open() 是 async —— 连接是 C++ 里的 sqlite3*。 返回的是实例，连接 id 在实例内部，开发者不用管。 库文件落在应用数据目录的 db/ 下（多垫一层是为了跟 WebView2 的浏览器数据隔开）。

建表（db.exec）

exec 可以一次跑多条语句，适合建表和初始化。 它不支持参数绑定 —— 需要绑定就用 run / get / all。

写入（db.run + 参数绑定）

两种都收：数组按位置绑 ?，对象按名字绑 :name / @name / $name。 返回 { changes, lastInsertRowid }。 一律走绑定，不要自己拼 SQL 字符串。

查询（db.get / db.all）

没查到时 get 返回 null 而不报错 —— 查不到是正常结果，不是失败。

更新与删除（db.run）

看 changes：UPDATE / DELETE 的实际影响行数，条件没命中就是 0（也不是失败）。

类型映射

INTEGER / REAL → number，TEXT → string，BLOB → base64 字符串，NULL → null。 SQLite 的 INTEGER 是 64 位的，转成 JS number 后超过 2^53 会丢精度。

事务（db.exec 多语句）

没有专门的 transaction API：连接是长住的，用 exec('BEGIN') / exec('COMMIT') 手写即可。 注意：每次调用都是一次异步往返，BEGIN 和 COMMIT 之间会漏进别的操作， 事务期间别并发操作同一个连接。

错误处理与安全

错误里带 SQLite 的 errmsg，不是光秃秃的错误码。 ATTACH 被禁：否则任意 SQL 能把磁盘上别的库挂进来， Db.open 那边的路径约定就形同虚设。
