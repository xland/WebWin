发一个请求

请求体要发 JSON 的话，自己 JSON.stringify 并在请求头里写 {"content-type":"application/json"} —— 原生层不会替你猜。

对比：Http.fetch 不走 CORS，页面里的 fetch 走

页面跑在 https://{appId} 这个全世界都不认识的 origin 上， 所以页面里直接 fetch() 会被 CORS 拒；Http.fetch() 走 C++ 的 WinHTTP，不经渲染进程，没有 CORS 这回事。这一条就是本能力的全部意义。

什么会 reject，什么不会

网络层失败（DNS 解析不了 / 连不上 / 超时 / 证书不过）才 reject； 404 / 500 是服务端给的正常答复，照常 resolve，要看 res.ok。 这跟 web fetch 一致。

响应头与 body

响应头的 key 统一小写，所以取的时候写 res.headers['content-type']。
